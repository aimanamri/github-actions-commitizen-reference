# GitHub Actions + Commitizen reference

A small, working Python repo I keep as a **cheat sheet** for:

- GitHub Actions (CI on pull requests, automated release on `main`)
- Conventional Commits and Commitizen (`cz commit`, `cz check`)
- Automatic version bumping and `CHANGELOG.md`
- Naming conventions (branches, commits, tags, files)

Copy the files you need into a new project.

## The flow in one picture

```
feature branch ──commit (feat:/fix:/...)──► pull request ──► CI: tests + commit-lint
                                                  │
                                              merge to main
                                                  │
                                   bump-version workflow runs
                                                  │
              cz bump: new version + CHANGELOG.md + git tag (e.g. 2.1.0)
```

## Layout

```
.github/workflows/
  ci.yml             tests (OS x Python matrix) + commit message check, on PRs to main
  bump-version.yml   commitizen bump + changelog + tag, on push to main
docs/
  01-github-actions.md       workflow anatomy, triggers, matrix, gotchas
  02-conventional-commits.md commit types, format, examples
  03-commitizen-versioning.md  setup, bump rules, changelog, pre-commit
  04-naming-conventions.md   branches, tags, workflows, files
src/calculator.py            dummy code under test
tests/test_calculator.py     pytest tests
pyproject.toml               commitizen + pytest config
.pre-commit-config.yaml      local commit-message hooks
requirements-dev.txt         pytest, commitizen, pre-commit
CHANGELOG.md                 generated by commitizen, do not edit by hand
```

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
pre-commit install --hook-type commit-msg --hook-type pre-push
pytest
```

Commit with the guided prompt:

```bash
git add . && cz commit
```

## Cheat sheet

| Task | Command |
| --- | --- |
| Guided commit | `cz commit` (alias `cz c`) |
| Validate last message | `cz check --rev-range HEAD~1..HEAD` |
| Preview next version | `cz bump --dry-run` |
| Bump + changelog + tag | `cz bump` then `git push --follow-tags` |
| First release in a repo | `cz bump --yes --increment PATCH` |
| Regenerate changelog | `cz changelog` |

## Repo-side setup (one time)

- Settings → Actions → General → Workflow permissions: **Read and write**, so `bump-version.yml` can push the bump commit and tag.
- If `main` is a protected branch, the default `GITHUB_TOKEN` cannot push to it. Use a PAT or a GitHub App token, or allow the bot to bypass.
- Optional: mark `CI / test` and `CI / commit-lint` as required status checks.
